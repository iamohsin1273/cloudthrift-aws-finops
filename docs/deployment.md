# Deployment and cleanup

No resources have been deployed. Obtain explicit approval before bootstrap, apply, invocation, enabling Cost Explorer, cleanup, or any other account changes. Use a dedicated test account and temporary credentials with only the necessary permissions. Verify the account and region first. Terraform plans can read AWS and may expose sensitive information; protect plan files.

1. Install Python 3.12, Terraform >= 1.10, AWS CLI and dependencies; run the local checks in the README. Enable Cost Explorer only with separate approval if not already enabled; data may take time to appear.
2. Choose a globally unique state bucket name and restrict its administrators. Bootstrap uses local state. After approval, initialize and plan `terraform/bootstrap`, then explicitly apply the reviewed plan. Preserve its local state securely. State bucket `prevent_destroy` deliberately requires a conscious configuration change for removal.
3. Package: `py -3.12 scripts/package_lambda.py`. Copy `terraform/environments/dev/terraform.tfvars.example` to `terraform.tfvars` and set the explicit regions and schedule. Never commit the local file.
4. Initialize the dev backend, substituting your bucket and region: `terraform -chdir=terraform/environments/dev init -backend-config="bucket=YOUR-STATE-BUCKET" -backend-config="key=cloudthrift/dev.tfstate" -backend-config="region=ap-south-1" -backend-config="use_lockfile=true"`. Terraform needs appropriate S3 state and `.tflock` object permissions including deletion of the lock. For an existing local state, use `init -migrate-state` and verify before removing the local copy.
5. Run `terraform -chdir=terraform/environments/dev plan -out=cloudthrift.tfplan`, inspect every change and cost. Apply only after explicit approval. The configuration creates a scheduled collector immediately; review schedule and charges before applying.
6. After separate approval for real invocation, inspect Lambda logs and the S3 report and confirm the configured Scheduler runs. A partial report deliberately results in Lambda failure. Check billing permissions, Cost Explorer activation, region permissions and CloudWatch logs for failure types.

Cleanup requires separate explicit approval: review a destroy plan and retention obligations first. Versioned report objects and delete markers must be handled deliberately before the bucket can be removed. Terraform state bucket and bootstrap state are separate and should be retained until all managed resources are removed and state is backed up. The bootstrap bucket has `prevent_destroy`; remove that protection only after an intentional review. Never assume Terraform destroy removes billable resources outside this stack.
