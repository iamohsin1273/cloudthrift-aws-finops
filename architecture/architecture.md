# Architecture and report contract

Scheduler invokes Lambda asynchronously once daily at 06:00 Asia/Kolkata by default. Lambda reads Cost Explorer in us-east-1, paginates EC2 in each configured region, writes a JSON report to S3 and logs a structured completion event. A scheduled time is hashed for the key so repeated deliveries for the same schedule overwrite the same key; S3 versioning retains prior versions. Reserved concurrency limits overlap but does not guarantee a single execution or avoid duplicate API charges. Lambda asynchronous retries are separate from Scheduler delivery retries.

Schema `1.0`: `generated_at` is UTC ISO-8601; `account_id` is the caller account; `billing_scope` describes the Cost Explorer permissions-dependent view; `inventory_regions` is the configured list. `cost_summary` has an inclusive start and exclusive end, daily per-currency decimal strings, daily `estimated` flags, and month-to-date totals. The end excludes the current UTC day; on the first, the prior day is included in daily results but not the new month total. `service_costs` are month-to-date totals per service and currency. `ec2_inventory` contains IDs, type, state, region, AZ, launch time, tags and ASG tag where available. `collection_status` has `ok` and, on failure, `error_type` for each source. A null cost summary or false status means incomplete data, not zero spending. S3 failures fail the invocation; partial collection is uploaded then the invocation fails for visibility/retry. STS failure prevents any report.

Cost estimates, anomaly detection, EBS, governance, alerts and remediation are not yet part of this data flow. Cost Explorer uses unblended cost, not an invoice or amortized effective cost; billing data can be delayed and revised.
